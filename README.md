# switchdesk

Программный переключатель мыши и клавиатуры (+ текстовый буфер обмена) между компьютерами.
По горячей клавише ваш ввод уходит на общий компьютер, повторное нажатие возвращает его обратно.
Один общий компьютер — несколько пользователей по очереди: кто подключился последним, тот и
управляет, предыдущего возвращает на его собственный компьютер.

Только Windows. Без внешних зависимостей, кроме `windows-sys`. Потоки вместо async-рантайма.

## Состав

| Крейт      | Что делает |
|------------|------------|
| `proto`    | Бинарный протокол (кадры поверх TCP), склейка движений мыши. Тесты. |
| `winutil`  | Буфер обмена, `SendInput`, служебное окно. |
| `host`     | Работает на общем компьютере: принимает ввод, внедряет его, ведёт очередь «один активный». |
| `client`   | Работает на ваших компьютерах: хуки ввода, горячая клавиша, сеть. |
| `update`   | Проверка, загрузка (WinHTTP) и установка обновлений, проверка подписи. |
| `tools/sign` | Утилита релизов: ключи и подпись установщика (не входит в поставку). |

## Установка

Скачайте `switchdesk-setup.exe` со страницы [Releases](https://github.com/m-dan12/switchdesk/releases/latest)
и запустите. Мастер спросит, что ставить (клиент, хост или оба), адрес хоста / адрес прослушивания
и нужен ли автозапуск. По умолчанию установка идёт в профиль пользователя (без UAC); режим
«для всех пользователей» выбирается в начале мастера. Ярлыки создаются в меню «Пуск» (и в автозапуске).

SmartScreen при первом запуске может предупредить: установщик не имеет цифровой подписи Authenticode.
Подлинность обновлений защищена отдельно — подписью ed25519 (см. ниже).

## Обновления

- При каждом запуске `switchdesk-client` / `switchdesk-host` проверяют последний релиз на GitHub.
  Если он новее, проверяется подпись, запускается тихая установка и программа перезапускается
  с теми же аргументами. Сбой проверки (нет сети и т. п.) на запуск не влияет.
- `--check-update` — только проверить; `--update` — скачать и установить; `--version` — версия;
  `--no-auto-update` — не обновляться при запуске.
- Установщик подписан ed25519: подпись покрывает версию и файл, публичный ключ зашит в программу
  (`update/src/lib.rs`). Адреса загрузки принимаются только с `github.com/m-dan12/switchdesk/releases/download/<тег>/`.

## Выпуск версии

1. Поднять `version` в `[workspace.package]` корневого `Cargo.toml`, закоммитить в `main`.
2. `git tag vX.Y.Z && git push origin vX.Y.Z` — workflow `Release` соберёт установщик, подпишет и
   опубликует релиз. Нужен секрет репозитория `UPDATE_SIGNING_KEY`
   (новая пара ключей: `cargo run -p switchdesk-sign -- keygen`; публичную часть — в `PUBLIC_KEY_HEX`).

## Сборка из исходников

```
cargo build --release
```

## Запуск

На общем компьютере (адрес — его адрес в Tailscale):

```
switchdesk-host --bind 100.x.y.z:7878
```

На своём компьютере:

```
switchdesk-client --host server.tailnet.ts.net:7878 --name Даниил
```

Дальше: **Ctrl+Alt+F12** — переключить ввод на хост / обратно.

### Безопасность

Хост принимает ввод от любого, кто достучится до порта, **шифрования и аутентификации в самом
протоколе нет** — расчёт на Tailscale (WireGuard). Поэтому:

1. Привязывайте `--bind` к адресу Tailscale, а не к `0.0.0.0`. По умолчанию хост слушает только
   `127.0.0.1`.
2. Ограничьте доступ к порту ACL-ами Tailscale (тег на хост + разрешение только нужным людям).
3. Проверка личности клиента через `tailscale whois` пока не реализована (этап 5 плана).

## Что реализовано

- Мышь (Raw Input — настоящие дельты, без упора в край экрана), колесо, клавиатура по сканкодам.
- Горячая клавиша обрабатывается локально в хуке: из «удалённого» режима есть выход даже при
  зависшей сети. Дополнительно: heartbeat раз в секунду, таймаут хоста 5 с, автоматический
  возврат на свой компьютер при обрыве.
- Один активный клиент. Новый вытесняет прежнего (тот получает сообщение и звуковой сигнал);
  при кике и отключении хост отпускает все зажатые клавиши/кнопки и очищает буфер обмена.
- Физический ввод на хосте имеет приоритет: пока кто-то работает за ним (и ещё
  `--grace-ms`, по умолчанию 1.5 с), удалённый ввод игнорируется, клиент получает сигнал.
  Копирование на хосте в этот момент не уходит удалённому пользователю.
- Буфер обмена: только **текст**, до 1 МиБ, в обе стороны, пока идёт сессия. Не синхронизируется
  то, что менеджер паролей пометил как исключаемое. На хосте текст пишется с флагами «не в
  историю Win+V и не в облако».

## Известные ограничения

- Не проверялось на реальном Windows (см. «Разработка»): первый запуск — это и есть первый тест.
- Хост — обычный процесс в сессии пользователя. Окна «от администратора» не принимают
  внедряемый ввод (UIPI) — запускайте хост от администратора. Экран блокировки, UAC и
  Ctrl+Alt+Del недоступны; для них нужна служба SYSTEM.
- Мышь: абсолютные устройства (тачпады, RDP, некоторые виртуалки) не поддерживаются.
  Хост применяет к дельтам свою кривую ускорения указателя.
- Раскладки: клавиши идут по сканкодам, раскладка и её переключение — на стороне хоста.
- Если при входе в сессию у вас зажата Win, возврат её отпускания может открыть меню «Пуск».
- Картинки и файлы в буфере обмена, named pipe для Radial Menu, служба — следующие этапы.
- Консольное приложение: для автозапуска без окна добавьте `#![windows_subsystem = "windows"]`
  и логирование в файл.

## Разработка

Windows-таргет Rust может быть недоступен (например, в CI-песочнице), но платформенно-независимая
логика (`proto`, `host::held`, `host::session`) тестируется где угодно:

```
cargo test --workspace
```

Windows-код можно проверить на типы под Linux/macOS — он компилируется при `--cfg switchdesk_check`
(линковка при этом не выполняется):

```
RUSTFLAGS="--cfg switchdesk_check" cargo check --workspace
```

Это проверяет типы и сигнатуры `windows-sys`, но не поведение.
