# switchdesk

Программный переключатель мыши и клавиатуры (+ текстовый буфер обмена) между компьютерами.
По горячей клавише ваш ввод уходит на общий компьютер, повторное нажатие возвращает его обратно.
Один общий компьютер — несколько пользователей по очереди: кто подключился последним, тот и
управляет, предыдущего возвращает на его собственный компьютер.

Только Windows. Без внешних зависимостей, кроме `windows-sys`. Потоки вместо async-рантайма.

## Как это работает

Switchdesk — одно приложение для Windows. Установите его на каждый компьютер: каждый и **принимает**
ввод от других, и может **отправить** ваш ввод на выбранный компьютер. Окно с настройками,
значок в трее, горячая клавиша **Ctrl+Alt+F12** (переключить ввод на выбранный компьютер / вернуться).

Первый запуск: в окне вы видите адрес этого компьютера (в Tailscale) — введите его на втором
компьютере в разделе «Компьютеры», выберите его и нажмите «Переключить».

## Состав

| Крейт      | Что делает |
|------------|------------|
| `proto`    | Бинарный протокол (кадры поверх TCP), склейка движений мыши. |
| `winutil`  | Буфер обмена, `SendInput`, служебные окна, автозапуск, адрес Tailscale. |
| `core`     | Настройки, состояние, приём ввода (хост), отправка ввода (клиент), движок. |
| `update`   | Проверка, загрузка (WinHTTP) и установка обновлений, проверка подписи. |
| `app`      | Окно (egui) и значок в трее — собирается в `switchdesk.exe`. |
| `tools/sign` | Утилита релизов: ключи и подпись установщика (не входит в поставку). |

## Установка

Скачайте `switchdesk-setup.exe` со страницы [Releases](https://github.com/m-dan12/switchdesk/releases/latest)
и запустите. Установка идёт в профиль пользователя (без UAC); ярлык создаётся в меню «Пуск».
SmartScreen/антивирус может предупредить: у установщика нет подписи Authenticode, а программа
перехватывает ввод и поэтому похожа на кейлоггер для эвристик. Подлинность файла можно сверить
по `SHA256SUMS.txt` из релиза.

## Обновления

- Приложение проверяет релизы на GitHub при запуске и раз в 6 часов. Если включено
  «Обновляться автоматически» и никто не пользуется вводом, оно само скачивает, проверяет
  подпись и ставит новую версию; иначе показывает кнопку «Обновить» в окне.
- Консольные команды: `switchdesk --version`, `--check-update`, `--update`
  (запускайте через `Start-Process -Wait`, т. к. приложение оконное).
- Установщик подписан ed25519: подпись покрывает версию и файл, публичный ключ зашит в программу
  (`update/src/lib.rs`). Адреса загрузки принимаются только с `github.com/m-dan12/switchdesk/releases/download/<тег>/`.

## Выпуск версии

1. Поднять `version` в `[workspace.package]` корневого `Cargo.toml`, закоммитить в `main`.
2. Запустить Actions → Release → Run workflow (или поставить тег `vX.Y.Z`): workflow соберёт
   установщик, подпишет и опубликует релиз. Нужен секрет репозитория `UPDATE_SIGNING_KEY`
   (новая пара ключей: `cargo run -p switchdesk-sign -- keygen`; публичную часть — в `PUBLIC_KEY_HEX`).

## Сборка из исходников

```
cargo build --release
```

Нужен Rust для Windows (`x86_64-pc-windows-msvc`). Результат: `target\release\switchdesk.exe`.
В CI на каждом push собирается окно и публикуются снимки интерфейса в ветку `ui-preview`.

### Безопасность

Приложение принимает ввод от любого, кто достучится до порта, **шифрования и аутентификации в самом
протоколе нет** — расчёт на Tailscale (WireGuard). Поэтому:

1. По умолчанию приложение слушает только адрес Tailscale (`100.x.y.z`), а не все интерфейсы.
2. Ограничьте доступ к порту ACL-ами Tailscale.
3. Проверка личности клиента (общий ключ / `tailscale whois`) пока не реализована.

## Что реализовано

- Мышь (Raw Input — настоящие дельты, без упора в край экрана), колесо, клавиатура по сканкодам.
- Горячая клавиша обрабатывается локально в хуке: из «удалённого» режима есть выход даже при
  зависшей сети. Heartbeat раз в секунду, таймаут 5 с, автоматический возврат при обрыве.
- Один активный управляющий. Новый вытесняет прежнего (тот получает сообщение и звуковой сигнал);
  при кике и отключении принимающий отпускает все зажатые клавиши/кнопки и очищает буфер обмена.
  Компьютер, который сам управляет другим, не принимает ввод, и наоборот.
- Физический ввод за принимающим компьютером имеет приоритет: пока кто-то работает за ним (и ещё
  «паузу» — 1,5 с по умолчанию), удалённый ввод игнорируется.
- Буфер обмена: только **текст**, до 1 МиБ, в обе стороны, пока идёт сессия. Не синхронизируется
  то, что менеджер паролей пометил как исключаемое.
- Окно скрывается в трей (крестик), выход — из меню значка.

## Известные ограничения

- Приложение — обычный процесс в сессии пользователя. процесс в сессии пользователя. Окна «от администратора» не принимают
  внедряемый ввод (UIPI) — запускайте хост от администратора. Экран блокировки, UAC и
  Ctrl+Alt+Del недоступны; для них нужна служба SYSTEM.
- Мышь: абсолютные устройства (тачпады, RDP, некоторые виртуалки) не поддерживаются.
  Принимающий компьютер применяет к дельтам свою кривую ускорения указателя.
- Раскладки: клавиши идут по сканкодам, раскладка и её переключение — на стороне принимающего компьютера.
- Если при входе в сессию у вас зажата Win, возврат её отпускания может открыть меню «Пуск».
- Картинки и файлы в буфере обмена, named pipe для Radial Menu, служба — следующие этапы.
- Журнал работы: `%APPDATA%\\Switchdesk\\switchdesk.log`, настройки — `settings.json` там же.

## Разработка

Windows-таргет Rust может быть недоступен (например, в CI-песочнице), но платформенно-независимая
логика (`proto`, `host::held`, `host::session`) тестируется где угодно:

```
cargo test --workspace
```

Windows-код можно проверить на типы под Linux/macOS — он компилируется при `--cfg switchdesk_check`
(линковка при этом не выполняется):

```
RUSTFLAGS="--cfg switchdesk_check" cargo check --workspace
```

Это проверяет типы и сигнатуры `windows-sys`, но не поведение.
